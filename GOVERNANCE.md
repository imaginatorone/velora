# Governance

Velora is maintained in public. Technical discussion, design decisions, and
review happen in GitHub issues and pull requests whenever possible.

## Roles

### Contributors

Anyone who reports a reproducible bug, improves documentation, reviews a
change, or submits code is a contributor.

### Maintainers

Maintainers triage issues, review pull requests, keep releases buildable, and
apply the project's contribution and conduct rules. Maintainer access is based
on sustained, constructive work and sound judgment, not on a contribution
count.

### Project leadership

[`@imaginatorone`](https://github.com/imaginatorone) is the project owner and
lead maintainer. The owner sets the long-term direction and has the final
decision when maintainer consensus is not possible.

[`@Lucferdev`](https://github.com/Lucferdev) is a project co-author and
maintainer, contributing to design, implementation, and project maintenance.

## Decisions

Routine changes are decided through pull request review. Changes to VelScript
syntax, compatibility, dependencies, licensing, or project direction should
start with an issue and allow time for contributor feedback.

The preferred outcome is rough consensus backed by working code and tests. If
consensus is not possible, maintainers document the tradeoff before the project
owner makes the final call.

## Becoming a maintainer

An existing maintainer may nominate a contributor who has shown reliable
technical work, respectful review, and care for cross-platform behavior. The
project owner confirms maintainer access. Access may be removed after prolonged
inactivity or when needed to protect the project.
